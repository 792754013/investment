# 个人投资研究方案 v2（草案）

- 版本：v2.0 草案
- 日期：2026-11-02
- 状态：**草案，待用户评审**。评审通过后，本文替换 `docs/plan.md`，v1.1 归档到 `docs/archive/plan-v1.1.md`。
- 依据：v1.1 的两期研究结果，包括：
  - `docs/research/G1-conclusion.md`：加密资金费 carry；
  - `docs/research/CB-G1-conclusion.md`、`C1v5-events-overlay.md`：可转债双低和事件规则；
  - 2026-11-02 对出发点的复盘。

> 本文是研究方案，不构成投资建议。第 4 节"底仓"只给出需要你自己决定的框架，不给具体比例。如果需要个性化的配置建议，请咨询持牌顾问。

**v2 相对 v1.1 的主要变化：**

1. **出发点**：从"做一个结构性策略平台"改为三层：
   - 被动配置打底；
   - 规则红利做增量；
   - 研究作为机会管道和学习投入。
2. **选机会的标准反过来**：v1 优先选"数据全、易自动化"的机会，这恰恰是最拥挤的。v2 优先选"别人难以低成本复制"的机会，准入问题新增第 7 问"拥挤度"。
3. **工程大幅收缩**：Go 平台、guardian、VPS、Grafana 这一整套全部挂起。默认执行方式改为"Python 脚本 + 本地 Mac + 提醒 + 手工执行"。只有某个机会证明自己"大而稳、必须自动化"之后，才按 v1.1 的设计启动工程。
4. **每个机会单独过 G0**：要求给出按计划资金算的绝对金额，每年能多赚多少元，不只看年化。
5. **保留研究纪律**：封存样本外、试验计数、G1 门槛先于结果、悲观成本、选高原、独立复核。这是两期研究中真正起作用的部分。

## 0. 摘要

| 项 | 内容 |
|---|---|
| 目标 | 在个人小资金（A 股约 5 万～10 万元）下，长期稳定地提高资产的风险调整后收益。研究能力是手段，也是学习投入 |
| 三层结构 | **底仓**：被动配置，用户自定政策，低成本、低维护。**增量**：规则红利型机会，有限额、手工几分钟、偶尔出现。**研究**：机会管道，按纪律快速否证 |
| 不做的事 | 纯价格预测和机器学习择时；已经出名的拥挤策略；验证之前的重工程；在法律风险没有确认之前做加密交易 |
| 判断标准 | 准入七问，新增"拥挤度"；每个机会单独过 G0（绝对金额）和 G1（样本外、悲观成本） |
| 执行方式 | 默认手工。脚本只负责数据、信号和提醒；自动下单只在 G1 通过、并且手工明显做不过来时才考虑 |
| 下一步 | ① 用户确定底仓政策并开户；② 对 QDII / LOF 溢价申购做 1～2 天的快速否证（OPP-003） |

## 1. v1.1 的结果与教训

### 1.1 两期结果

| | 加密资金费 carry（OPP-001） | 可转债双低 + 事件（OPP-002） |
|---|---|---|
| 样本内结果 | 18 组最好的一组净年化 +0.4%。有利口径下连 USDT 活期（4.48%）都跑不赢 | 每年比中证转债指数多赚约 4～9pp，但 2025 年大幅跑输；规则改了 5 轮，最后 27 组里只有 2 组刚好过线 |
| 失败原因 | 成本 > 收益；机会已被大规模产品吃掉 | 超额不稳定；过线依赖少数事件的路径；最低佣金会让它直接不过 |
| 试验次数 | 50 | 249 |
| 结论 | 证伪，retired | 证据不足，retired（封存段没有解封） |
| 花费 | 研究时间，没有写执行代码，没有亏钱 | 同左 |

### 1.2 什么是对的

- **"先验证、后工程"和各道闸门**：两个方向都在写执行代码之前被否证。
- **研究纪律**：
  - 封存段拦下了一次"看起来过线"的解封；
  - 试验计数让"试了 249 次"这个事实无法被忽略；
  - 独立复核两次都发现了报告里的错误。
- **基准选同风险的"什么都不做"**：资金费比交易所活期，可转债比转债指数。正是这个基准让"表面年化"露了底。

### 1.3 什么是错的

1. **选机会的标准和"有没有优势"相反**：
   - v1 把资金费排第一，理由是"API 完整、数据可回填、全自动"。但对你容易，对所有人都容易。
   - 两个方向都是同类机会里最出名的：资金费 carry 已被产品化，双低是散户圈最流行的转债策略。
2. **"容量小 → 机构不来 → 价差留给个人"这个推理漏了同类散户**：
   - 小容量挡得住机构，挡不住用同样免费数据和开源工具的大量个人量化玩家。
   - 真正的门槛是资格、额度、时间、麻烦、本地信息。
3. **工程投入和资金规模不匹配**：
   - G0 已经算出，这个规模下任何优势每年只有几千元；
   - 但方案设计了 12～18 人周的平台；
   - 而能拿到的机会，恰恰多半是最不需要平台的那种：限额、手工。
4. **"以赚钱为主"和资金规模冲突**：G0 写了警告（每小时 1～4 USD），但没有改变路线。

### 1.4 关于"预测"

两期结果**不支持**改做预测。理由：

- **过拟合**：可转债有清楚的经济学假设，试了 249 次，过线的结果仍然经不起"事件推后一天"的扰动。纯价格预测没有假设约束，过拟合只会更严重。v1.1 第 1.1 节放弃机器学习预测的理由仍然成立。
- **结构和预测的界线并不清楚**：
  - 双低本质上是价值因子；
  - 下修公告后的漂移本质上是"市场对公开信息反应不足"。

  真正的标准不是"预测还是结构"，而是"能不能说清楚是谁在付钱、为什么别人拿不走"。
- **有长期证据的低频因子**（价值、红利、低波动、小盘），通过指数基金或指数增强基金就能低成本拿到。自己做没有成本优势，只适合当作学习。
- **例外**：如果你有某个行业的一线信息，基本面判断可能有优势。这属于信息优势，需要的是记录和复盘的纪律，不需要建模平台。

## 2. 核心概念与判断标准

### 2.1 收益来源（沿用 v1.1 的四种机制，补充门槛要求）

| 机制 | 例子 | v2 的补充要求 |
|---|---|---|
| 偏好溢价 | 杠杆多头付资金费；散户为场内 QDII 付溢价 | 必须说明为什么溢价没有被同类散户套平 |
| 被迫交易 | 指数调样、强平 | 必须说明被迫方的规模，以及这个效应近年有没有被压缩 |
| 规则约束 | 外汇额度、限购、投资者适当性门槛 | **v2 优先**：规则本身就是门槛 |
| 摩擦成本 | 手工申购、跨市场操作、逐只阅读条款 | 只有摩擦对大多数人都真实存在时才算数。用免费工具一键就能做的，不算摩擦 |

### 2.2 准入七问（v1.1 的六问 + 第 7 问）

任何机会进入研究前，必须在机会卡片里回答：

1. 对手方是谁？他为什么愿意或者必须付这笔钱？
2. 机构为什么不来？是容量、合规，还是太麻烦？
3. 容量多大？
4. 最坏情况是什么？
5. 它会怎么消失？
6. 你的成本优势是什么？
7. **拥挤度：还有谁能用和你一样低的成本做这件事？**
   - 如果答案是"任何一个会用 akshare 或交易所 API 的人"，默认这个机会已经被套平。除非数据显示它仍然存在，并且能说明原因。
   - 加分的门槛有：
     - 需要特定账户、资格或额度；
     - 必须手工操作，无法批量化；
     - 信息分散在公告和条款里，需要逐条阅读；
     - 大多数人不愿意承担的小麻烦或短期风险。

答不清第 1 题或第 7 题的，不做。

### 2.3 G0：每个机会单独算绝对金额

按计划资金和悲观成本，估算"每年比基准多赚多少元"：
- 估算值低于**最低值得做的金额**（待用户确定，见第 9 节），直接放弃，不进入回测。
- 估算要用最便宜的数据，1～2 天内完成。

### 2.4 研究纪律（不变）

- **封存样本外**：沿用 `research/seal.toml`，2026-05-01 起封存。只通过 `lab.lake.scan()` 读数据。解封需要用户同意，而且只有一次。
- **试验日志**：每次回测都要记录，`research/trials.csv` 只追加，不删改。
- **G1 门槛先于结果**：每个机会在规则回测之前，写好并提交自己的 G1 条件。
- **悲观成本**；**选高原，不选尖峰**。
- **独立复核**：G1 结论由一个不带前文的 agent 复核。
- **前向记录**（可选）：样本外太短时，冻结规则，按日记录。

## 3. 目标与成功标准

### 3.1 目标

1. **底仓**：有一份书面的配置政策，按规则执行和再平衡；每年复盘一次。
2. **增量**：每年最多投入少量机会，每个都要先过 G0 和 G1，执行成本以"每次手工几分钟"为上限。
3. **研究**：维持一个机会管道，按纪律快速否证；保留数据和工具的积累。

### 3.2 非目标

- 纯价格预测、机器学习择时、高频交易、做市。
- 在没有证明需要之前，搭建自动交易平台、多交易所接入、LLM 发现层。
- 管理他人资金。
- 法律风险没有确认之前，做境外加密交易（见第 8 节）。

### 3.3 成功标准（每年复盘）

- 底仓按政策执行，偏离和再平衡都有记录。
- 增量部分的每个机会都有"实际 vs 研究预期"的对照，扣除成本后为正；否则停止。
- 研究部分的每个机会都有结论文件，不论正负。

## 4. 底仓：被动配置（由用户确定政策）

底仓不需要研究优势，需要的是**纪律和低成本**。它也是增量机会要跑赢的基准。

需要你自己确定、并写成一页"投资政策说明"的内容：

| 项 | 需要确定的内容 |
|---|---|
| 资金范围 | 底仓总额；应急资金单独留出，不计入 |
| 风险承受 | 能接受的最大回撤（比如"下跌多少会让你卖出"） |
| 资产类别 | 比如 A 股宽基指数、境外指数、债券或国债、货币基金。用哪些类别、各占多少，由你决定 |
| 工具 | 低费率的指数 ETF 或指数基金。注意场内 QDII 的溢价，溢价高时不要在场内买 |
| 再平衡规则 | 定期（比如每年）或者按偏离阈值触发 |
| 现金管理 | 货币基金；季末、年末关注国债逆回购的利率高峰 |

研究可以提供的支持是：用免费数据回看某个配置在历史上的回撤和再平衡效果，**但不替你选比例**。

## 5. 机会管道 v2

按"门槛高、对你方便、能快速否证"排序。

| 编号 | 机会 | 机制 | 门槛（为什么别人不做） | 拥挤度 | 资格 | 状态 |
|---|---|---|---|---|---|---|
| OPP-003 | 场内 QDII / LOF 溢价申购套利 | 规则约束：外汇额度 | 每日限额小，机构不做；需要手工场外申购、转托管或场内卖出 | 中：集思录有溢价数据，但限额本身限制了套利的规模 | 普通 A 股账户、基金账户 | **下一个快速否证** |
| OPP-004 | 封闭式 / 定期开放基金折价收敛 | 规则约束：封闭期 | 品种少、容量小 | 低到中 | 普通账户 | 候选，可以和 OPP-003 一起做 |
| OPP-005 | 中小盘指数调样 | 被迫交易 | 大指数的效应已被压缩，中小盘待验证 | 中到高 | 普通账户 | 候选。可以复用可转债阶段的公告和事件研究工具 |
| — | 季末、年末逆回购 | 规则红利 | 几乎没有门槛，但多数人不关注 | 高，但收益本来就是给所有人的 | 普通账户 | 不需要研究，放进底仓的现金管理 |
| OPP-002 | 可转债下修事件（单独） | 规则约束 | — | — | 转债权限，需要 24 个月交易经验 | retired。积累新数据后可以重新评估 |
| OPP-001 | 加密资金费 carry 及同源变体 | 偏好溢价 | — | 高 | — | retired。跨所费率差、交割基差、统一账户 carry 赚的是同一种钱，不再单独研究 |

### 5.1 OPP-003 的快速否证（1～2 天）

1. 拉取过去 2～3 年场内 QDII / LOF 的每日溢价率、申购状态和限额（免费数据）。
2. 按悲观成本计算：
   - 申购费、卖出佣金；
   - T+2 左右期间净值和溢价的变化，取历史分布的不利分位。
3. 估算按限额每年能做多少次、每次赚多少元、合计多少元。
4. 合计低于 G0 的最低金额，就放弃；高于的话，写 G1 条件，进入回测。

## 6. 研究流程（每个机会）

```
建卡（七问）→ 快速否证（1～2 天，最便宜的数据）→ G0（绝对金额）
→ 写 G1 条件（用户确认、提交）→ 规则回测（只用样本内，记录试验次数）
→ 独立复核 → 用户决定：解封检验 / 前向记录 / 停止
→ 通过：小额手工执行 → 实际 vs 预期对照 → 扩大或停止
```

- 每一步都可以停，停下时写结论文件、更新卡片状态。
- 同一个机会，规则修改超过 3 轮仍然没过，默认停止。如果要继续，必须写明新的结构性理由，而不是新的参数。

## 7. 执行与工程

- **默认**：Python 脚本（`research/`）+ 本地 Mac + launchd 提醒 + 手工执行 + CSV 账本。
- **不做**：自动下单、券商接口、VPS、Go 平台、Grafana。
- **启动工程的条件**（全部满足）：
  1. 某个机会通过了 G1 和至少 3 个月的手工执行，实际收益与预期一致；
  2. 手工执行明显做不过来，或者执行偏差已经吃掉收益；
  3. 按实际资金算，每年的净收益明显超过工程投入的时间成本。

  满足后，再参考 v1.1 第 5～18 节的设计（归档版），只实现需要的部分。

## 8. 合规、账户与税务

- **A 股**：用户尚未开户。
  - 场内基金、ETF、逆回购只需要普通账户；
  - 可转债需要 24 个月交易经验，以及开通前 20 个交易日日均资产 10 万元。
  - 开户时问清楚各类品种的佣金和最低收费。
- **加密资产**：v1.1 第 23 节的法律风险提示继续有效。确认所在司法辖区允许之前，不做境外加密交易的研究和执行。
- **数据**：遵守各数据来源的服务条款，控制抓取频率，只供个人研究。
- **税务**：账本是申报依据，按所在地规定申报。

## 9. 待决问题（需要用户确定）

1. **项目的侧重**：更看重"赚钱"，还是"学习和练手"？
   - 侧重赚钱：底仓优先，研究只做门槛最高的少数机会；
   - 侧重学习：可以接受研究的期望收益很低，但要控制时间。
2. **G0 的最低值得做金额**：一个机会每年至少多赚多少元才值得投入。比如 1,000 元或 3,000 元。
3. **每月的研究时间预算**：比如每月几小时。
4. **底仓政策**：第 4 节的各项，由你自己确定，或者咨询持牌顾问。
5. **开户时间**。
6. **加密方向**：是彻底放弃，还是保留到确认法律风险之后。
